# super-dev-memory — 分层记忆系统

## 定位
构建**分层、可检索、自我进化**的记忆系统。每次任务自动沉淀经验，让整个套件越用越强、越用越"懂你"。

## 何时激活
- 每个子 Skill 任务完成后（自动触发）
- 遇到 Bug 并修复后
- 做出关键技术决策后
- 发现新的最佳实践
- 用户显式要求记录某事
- 套件定期维护（周/月）

## 记忆分层架构

```
Level 1: 会话记忆（Session Memory）
  └── 当前会话的短期上下文
      生命周期：单次对话
      
Level 2: 任务记忆（Task Memory）  
  └── 任务级别的经验记录
      生命周期：项目周期
      
Level 3: 项目记忆（Project Memory）
  └── 跨任务的项目级知识
      生命周期：项目存续
      
Level 4: 领域记忆（Domain Memory）
  └── 跨项目的通用经验 & 模式
      生命周期：永久
```

## Level 1: 会话记忆

### 记录内容
```
- 当前会话的目标和约束
- 已完成的子任务列表
- 进行中的决策上下文
- 用户偏好和反馈
```

### 操作
```
每次 Skill 激活：读取相关会话上下文
每次 Skill 完成：更新会话状态
会话结束：提取关键信息 → 升级到 Level 2
```

## Level 2: 任务记忆

### 文件结构
```
memory/
├── YYYY-MM-DD-task-name.md    # 任务记忆文件
├── index.md                    # 任务索引
└── patterns.md                 # 模式库
```

### 任务记忆模板
```markdown
# [日期] [任务类型] - [简述]

## 背景
- 任务来源：
- 相关需求：

## 关键决策
- 决策：...
- 原因：...
- 替代方案：...

## 实施记录
- 修改的文件：
- 新增的依赖：
- 架构变更：

## 遇到的问题
- 问题描述：
- 根因分析：
- 解决方案：
- 预防措施：

## 经验提炼
- 可复用模式：
- 新发现的最佳实践：
- 踩过的坑：
- 给未来自己的提示：

## 标签
#bug-fix #refactor #performance #security #ux #architecture
```

### 检索接口
```
memory.search(
    task_type=None,      # 任务类型过滤
    tags=[],             # 标签过滤
    keywords="",         # 关键词搜索
    time_range=None,     # 时间范围
    limit=10             # 返回数量
)
```

## Level 3: 项目记忆

### 记录内容
```
- 项目架构决策记录 (ADR)
- 技术栈和版本锁定
- 团队约定和编码规范
- 部署和运维知识
- 安全策略和合规要求
```

### 文件结构
```
project/
├── architecture.md       # 架构概览
├── tech-stack.md         # 技术栈详情
├── conventions.md        # 编码规范
├── deploy.md             # 部署指南
├── security.md           # 安全策略
└── adr/                  # 架构决策记录
    ├── 001-choice-of-framework.md
    ├── 002-database-strategy.md
    └── ...
```

## Level 4: 领域记忆

### 记录内容
```
- 跨项目通用设计模式
- 语言/框架最佳实践
- 安全漏洞模式库
- UI/UX 设计模式
- 重构技巧集合
```

### 更新机制
```
触发条件：同一模式在 ≥3 个项目中出现
更新流程：
  1. 从项目记忆中提取通用模式
  2. 去上下文化，提炼通用规则
  3. 添加到对应领域记忆文件
  4. 标记来源项目（可追溯）
```

## 记忆维护操作

### 定期清理
```
每周：归档过期会话记忆
每月：整理任务记忆，淘汰过时信息
每季：审查领域记忆，更新最佳实践
```

### 记忆压缩
```
触发条件：单文件超过 500 行
操作：
  1. 提取核心模式和关键教训
  2. 归档详细信息（链接到档案）
  3. 保留可检索摘要
```

## 与 Orchestrator 交互

```
任务开始时：
  orchestrator → memory.search(task_type, keywords)
  → 获取相关历史经验

任务完成时：
  orchestrator → memory.store(entry)
  → 沉淀本次经验

周期性：
  orchestrator → memory.maintain()
  → 清理和压缩
```

## 检索策略

### 相关性排序
1. 精确标签匹配（权重最高）
2. 同类型任务（次级权重）
3. 关键词匹配（基础权重）
4. 时间衰减（越新越相关）

### 上下文注入
```
检索到的经验自动注入到子 Skill 的激活上下文中：
- 以 "参考历史经验" 前缀
- 不超过 3 条最相关记录
- 包含具体可操作的建议
```

## 反模式警示

| 反模式 | 表现 | 纠正 |
|--------|------|------|
| 记忆膨胀 | 什么都记，检索困难 | 分级存储，定期压缩 |
| 记忆遗忘 | 从不回顾历史经验 | 任务开始前强制检索 |
| 孤立记忆 | 经验只有自己能理解 | 记录时预判未来读者 |
| 过时记忆 | 旧经验与新实践冲突 | 定期审查，标记版本 |
| 上下文污染 | 注入过多无关历史 | 严格限制检索数量和相关性 |
